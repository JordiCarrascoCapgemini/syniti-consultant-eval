# CLAUDE.md

Guidance for agents working in this repo. Read `README.md` for what the project is and
`HANDOFF.md` for how the tool works. This file only covers what an agent gets wrong.

## Hard invariants

**Never hand-edit anything in `tool/`.** Both apps are build output as of v7.0: the eval app
from `build/template.html`, the team summary from `build/template-team.html`. Edit a template
or `data/*.json`, then run the builder. A clean build reproduces the committed files exactly,
so any unexpected `git diff` on `tool/` after a build means you changed an input.

**Templates are read and written with `newline=""`.** Do not remove that. `build.py` used to
read with universal newlines and write with platform translation, which produced CRLF output
on Windows and LF output inside the Linux container from the same template.

Line endings: the repository stores **LF** for the templates and the built apps. Git may present
them as CRLF in a Windows working tree (`core.autocrlf`), which is fine and expected. Because
`build.py` preserves the template's endings byte-for-byte, the build is self-consistent on either
platform: LF template gives LF output on Linux, CRLF working copy gives CRLF output on Windows,
and `git diff -- tool/` stays clean in both. Do not "normalise" either file to fix an apparent
mismatch, and do not add a `.gitattributes` forcing CRLF - that would put CRLF into the repo and
Linux checkouts would then carry it into `deploy/nginx/*.conf` neighbours by habit.

**No em dashes anywhere in build output.** `build/build.py` hard-fails the build if one appears
(`build.py:47-48`, as the escape `"\u2014"`). Standing project rule is the plain hyphen `-`. This applies to prose in
`data/*.json` too, since that text is injected into the HTML. Keep it in this file and in
commit messages as well.

**Do not extend `build/build-scripts/`.** That `build2 -> build3 -> build4 -> build_final`
chain is fragile and chat-specific; `issues.md:81-82` says explicitly not to add to it.
`build/legacy/` is dead too. `build/build.py` is the only builder.

**`data/competencies.csv` and `Competency Matrix (simplified).xlsx` have no generator.** They
are derived from `data/competencies.json` but only ever regenerated by hand
(`build/README.md:30-31`, `HANDOFF.md:332-333`). If you change `competencies.json`, they are
now stale and you must say so.

## Build

```bash
python build/build.py
```

Run from the repo root. Use `python` on this Windows machine; the docs say `python3`.
`build/template.html:557-558` holds `__COMPS__` and `__LEARNING__`; `build/template-team.html:455`
holds `__COMPS__` only. The builder aborts if any `__UPPER__` token survives substitution.

Masters: `data/competencies.json` (78 competencies, short-keyed to `ref/area/t/d/e` by the
builder) and `data/learning-catalog.json` (keyed by the exact competency `area` string - that
string is the join key across the whole data layer, so renaming an area silently breaks the
learning mapping).

## Known duplication

`LIM-5` is **closed** as of v7.0: both apps are generated from `data/competencies.json`, and the
short-key conversion lives once in `refdata.py`, shared by `build/build.py` and the server's
`GET /api/reference`.

What remains is the scoring logic: `stats`/`band`/`expFor`/`deltaClass` in the eval app have
near-identical twins (`evalStats`/`bandFor`/`expForLevel`/`deltaClass`) in the team app, and the
team app's own source comment admits the copy. **Do not add a third copy in any language.** In
particular the server stores documents verbatim and computes nothing; `tests/test_expected_results.py`
asserts only figures the apps already computed and stored, for the same reason.

## Dockerization work: locked decisions

Design agreed 2026-07-28 and implemented in v7.0. Recorded in `issues.md` as `DEC-7` (repo home)
and `DEC-8` (which points back here). This list stays the reference. Do not relitigate one
without saying which one you are changing and why.

1. **Additive, not replacing.** The offline `file://` path keeps working exactly as today.
   The server adds optional login plus save/load. Both survive.
2. **Leads only, shared pool.** Only leads have accounts; any logged-in lead can read and write
   any evaluation. Consultants never log in. `created_by` is stamped for audit.
3. **JSONB document storage.** One row per evaluation holding the exact `syniti-skills-eval` v3
   payload, plus indexed columns. No scoring logic server-side - all math stays in the existing JS.
4. **`data/*.json` stays master.** The builder keeps baking it in for offline; the API also
   serves it at `GET /api/reference` so the served apps need no embedded copy.
5. **Python, FastAPI, uvicorn.** No Node anywhere. This repo has no `package.json` and needs none.
6. **Server-side session cookie.** argon2 hashes in a `users` table, `HttpOnly` +
   `SameSite=Strict`, first admin created at startup from a mandatory env var with no default.
   Implemented with a `sessions` table holding opaque random tokens, so there is no signing
   secret to manage and logout or deactivation takes effect immediately. That makes three
   tables, not the two originally sketched in decision 14.
7. **Runtime feature detection.** `location.protocol === 'file:'` short-circuits to offline with
   no network probe; otherwise probe `GET /api/health` once and reveal the server-only controls.
8. **Append-only writes.** Every save inserts; reads return the newest row per
   `(consultant, eval_date)`. No overwrite, no delete endpoint.
9. **Compose: app plus postgres.** Healthchecked, named volume for pgdata, `COOKIE_SECURE` as an
   env flag so adding TLS later is config rather than a rewrite.
10. **This repo is canonical again.** Done: `issues.md` now carries an "Un-archived (2026-07-28)"
    note above the superseded 2026-07-17 reconciliation, plus `DEC-7`, and `CHANGELOG.md` has a
    v7.0 entry.
11. **`test-data/` is a seed command plus an integration test.** A pytest test seeds a throwaway
    database, fetches through the API, and asserts the numbers in `test-data/EXPECTED_RESULTS.md`
    (team avg 3.01, delta -0.18, 70% pooled, 46 gaps, bands 4/3/9/4). Never auto-seed on boot.
12. **Minimal UI.** A save button and a load-from-server picker. Note: the templates had **no**
    modal pattern to reuse, so a small `.ovl` overlay was added to each, built from the existing
    brand-kit tokens. No full CRUD, no delete, no revision browser.
    The eval app also gained `srvApplyDoc()`, a real restore path: the pre-existing file importer
    only ever loaded a prior evaluation for *comparison* (`state.cmp`) and never repopulated the
    form. `state.plan` is keyed `area + "::" + title`, which is exactly what `learningPlan`
    entries carry, so the round trip is lossless.
13. **The team app comes under `build.py`** via `build/template-team.html`, which closes `LIM-5`.
    Extraction was verified two ways before the switch: the embedded literal parsed to data
    identical to `refdata.load_competencies()` (78 records), and the rebuild produced exactly
    **one** deleted line, the `COMPS` literal itself. Any future rebuild must behave the same.
14. **Plain idempotent SQL at startup.** `db/schema.sql`, `CREATE TABLE IF NOT EXISTS` for three
    tables (`users`, `sessions`, `evaluations`). No Alembic.

## Hosting on POCDAPP314 (DEC-9)

Deployed to one POCLAB host, **POCDAPP314 / 10.21.12.62**, running **RHEL 10.2**, with a
**host-level nginx** as shared reverse proxy. Host preparation:
`deploy/HOST-PREP-POCDAPP314.md`. Deployment: `deploy/DEPLOY-POCDAPP314.md`. Architecture:
`deploy/architecture.html`. Config: `deploy/nginx/`.

**RHEL ships Podman, not Docker.** Docker Engine comes from Docker's own repo and an `el10`
build must be confirmed to exist. If it does not, do not improvise a Podman deployment: that
changes the deployment mechanism, not one command, and DEC-10 would need revisiting.

**SELinux is enforcing.** nginx cannot proxy to a loopback port until
`setsebool -P httpd_can_network_connect 1` is set. Symptom is 502 on every request with
`Permission denied` in the nginx error log. This is the most commonly missed step here.

**The app must stay bound to loopback.** `docker-compose.yml` publishes
`127.0.0.1:${APP_PORT}:8000`. Changing that to `8001:8000` binds `0.0.0.0` and exposes the app
over plain HTTP on the lab network, bypassing TLS, the redirect and every security header.
`--forwarded-allow-ips=*` in the Dockerfile is only safe because of that binding; if one
changes, so must the other.

**nginx is not in the compose file, and must not be moved into it.** It is shared ingress for
several apps (dq-studio next), so an app-scoped `docker compose down` must not be able to drop
ingress for the others.

**One hostname per app on the shared IP**, routed by Host header and TLS SNI, each with its own
internal-CA certificate. Adding an app is one new file in `/etc/nginx/conf.d/` plus one DNS
record; loopback ports are registered in the runbook (8001 taken, 8002 reserved).

**Application stacks are deployed by Portainer from git (DEC-10), not by `docker compose` on
the host.** Secrets are Portainer stack environment variables, not a `.env` file; `.env.example`
still documents the variable names. Portainer itself is the one CLI-deployed stack
(`deploy/portainer/docker-compose.yml`) because it cannot deploy itself.

**Portainer mounts the Docker socket and is root-equivalent on the host.** It is published on
`127.0.0.1:9000` only and reached through nginx on its own FQDN. Do not publish 9443 or 8000,
do not remove the loopback binding, and set the IP allow-list in `deploy/nginx/portainer.conf`
before enabling that vhost. Its admin password is as sensitive as root on POCDAPP314.

**Two nginx snippet pairs exist for a reason.** `security-baseline.conf` is safe anywhere;
`csp-apps.conf` carries the app content-security-policy and must NOT be included in a
third-party UI vhost, because it breaks Portainer. `proxy-app.conf` sets `Connection ""` for
upstream keepalive and therefore breaks WebSockets; anything needing upgrades (Portainer) must
use `proxy-ws.conf`, which relies on the `$connection_upgrade` map defined in `00-default.conf`.

**Never `systemctl reload nginx` without a clean `nginx -t`.** A shared ingress means a broken
config restart takes down every app on the host, not just this one.

The nginx configs carry the placeholder hostname `skills-eval.poclab.local`. The real POCLAB
zone is unconfirmed; it appears in `server_name`, both cert paths, and the log paths.

## Blocking constraints on that work

**This must not hold a single real evaluation until it is fronted with TLS and
`COOKIE_SECURE=true`.** The default compose is HTTP.

**GDPR.** The database becomes a shared system of record for named-employee performance data on
EU staff, including `feedback.classification` and `feedback.recommendation`. Capgemini's Data
Privacy Officer must review the design before real evaluations land in it. Building against
`test-data/` is fine - that data is synthetic by design.

**Secrets.** `POSTGRES_PASSWORD` and the admin password come from a gitignored `.env` with no
defaults; compose should refuse to start without them. Never commit a real value, and never
fill one in on the user's behalf.
